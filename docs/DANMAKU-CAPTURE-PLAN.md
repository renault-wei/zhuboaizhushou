# 真实弹幕采集方案（选型文档 · 只输出不执行）

> 文档事实：写入侧已就绪（G3 `POST /api/lives/:id/danmaku` + `onDanmaku` 广播 + `live_danmaku` 落库均已验收），

> 不自带任何第三方破解 / 采集工具；若平台规则或风控变化，随时停用该项能力。

## 1. 背景与口径（已拍板）

- 目标：用**个人直播间**的真实弹幕做全链路实测 —— 弹幕进来 → AI 理解 → 语音回复 → 直播间听到。
- 官方企业通道（抖音开放平台：企业认证 + 弹幕 Webhook / 长连接）门槛高、需审核，**留到上架增强阶段**，不在本期实现。
- 全自动形态是「AI 主播」的终态，但自动读取自己直播间弹幕属于平台规则里需要谨慎对待的行为，
  因此先给三个不同自动化程度的口子，由你按风险偏好拍板走哪条。

## 2. 候选路径对比

| 路径 | 做什么 | 代码量 | 自动化 | 合规 / 风险 | 建议 |
|---|---|---|---|---|---|
| A 官方开放平台 | 企业认证后接官方弹幕回调 | 中 | 全自动 | 最正规，需企业资质 + 应用审核 | 上架增强阶段做，本期不做 |
| B 直播伴侣弹幕列表 · 人工中转 | 开播时直播伴侣能看到观众弹幕，你把它粘贴进工作台「测试弹幕注入」 | 0 | 人工 | 零风险（等价人工操作） | **首轮真实验收直接可用** |
| C 直播伴侣弹幕列表 · 屏幕 OCR 半自动 | 截屏弹幕列表区域 → OCR 成文字 → 写入网关 | 小 | 半自动 | 低（只读自己屏幕），OCR 有误读需兜底 | 可选：想省人工再加 |
| D 自用观看端 · 自动读取 | 自己账号在桌面端打开自己的直播间，读取页面已展示的弹幕转发网关 | 中 | 全自动 | 中：属平台机器人行为的灰色地带，有登录风控风险；只限个人直播间小流量自测 | 二期候选，需你确认风险可接受 |

说明：
- B/C/D 都复用现有 `POST /api/lives/:id/danmaku` 网关写入入口，业务侧（落库 / 互动引擎 / 语音出口）**零改动**。
- 无论哪条路，弹幕只是「触发源」，回复是否出声、播什么产品内容仍由现有 G4/G5 链路控制。

## 3. 三个待验证假设（决定实现细节，需你实测确认）

1. 主播本人用**自己的账号**在自己直播间里，直播伴侣的弹幕列表能看到观众的实时弹幕？（决定 B/C 可行性）
2. 桌面端以自己账号进入自己直播间页面，页面上是否能看到弹幕文本节点？（决定 D 可行性，需现场小流量试）
3. 真人副机（你自己）偶尔出镜说话时，弹幕里的提问是否需要跳过不播？（插话闪避已有独立决策项，与此无关，仅提醒）

## 4. 推荐顺序（供拍板）

1. **现在就做**：B 人工中转 —— 不写代码，先拿 1~2 位朋友的真实弹幕跑通「采集 → AI → 语音 → 直播间」闭环，验证真实弹幕形态与频控手感。
2. **若你接受屏幕读取形态**：在 B 跑通后加 C（OCR 半自动），代码量最小、风险最低，先于 D。
3. **D（全自动）放二期**：默认限自用、小流量、可一键停；等你实测确认平台无风控问题再做。

> 拍板入口：收到本方案后，请回「走 B / B+C / B+C+D」并确认可接受的自动化程度；确认前不写采集代码。

## 5. 不做清单（本期 / 长期红线）

- 不做抓包与协议逆向；不用非官方 SDK / 框架模拟抖音弹幕协议。
- 不做多账号、批量、刷量、黑产性质的采集。
- 不做绕过平台限流的任何手段；AI 智能直播角标恒开不关闭。
