# 多平台弹幕采集器开源候选审计（D0.1 · 2026-09-08）

> 状态：D0.1 已完成，结论 = **本期无可直接收录对象，`vendor/third_party/` 留空**；
> 全部候选只做机制参考、干净房自研；真实平台协议适配器是否自研 → 交 D2.5 合规门拍板。
> 触发：D 系列（多平台弹幕采集器内嵌）D0.1 逐仓许可证审计，见 `docs/DANMAKU-COLLECTOR-PLAN.md` §3。
> 审计口径：商用安全第一（AGENTS 红线：不直接携带第三方闭源 / 无许可 / 禁商用代码进产品）。

## 1. 审计方法

- 逐仓检查 LICENSE / README 授权声明（2026-09-08 复核），以仓库内文件原文为准，不以 GitHub 元数据页面为准。
- 收录判定遵守 `DANMAKU-COLLECTOR-PLAN.md` §3.1：MIT / Apache-2.0 且允许商用与再分发才可收；
  GPL / AGPL / 无 LICENSE / 明示禁商用 → 只读机制、干净房自研。
- 平台侧红线同步复核：不做抓包与私有 App 协议逆向、不模拟发包、不做绕过风控手段。

## 2. 关键事实（影响决策的两条）

1. **B 站协议文档仓库已永久关停**：`SocialSisterYi/bilibili-API-collect`（deprecated 分支）
   于 **2026-01-28** 收到 B 站委托律所警告函后永久关停，指控为「系统性整理 / 传播非公开 API」。
   结论：该仓库（及同类「系统性整理非公开协议」的资料）**不可作为本项目协议参考来源**。
2. **多数候选无 LICENSE 或明示禁商用**：直接可收录的实现极少；自研 + mock 自测是唯一干净路径。
