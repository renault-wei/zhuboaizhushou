# 话术生成太简陋 · 定位与新提示词设计（讨论，不执行）

> 客户方反馈：**生成的话术很简陋**。要求：① 设计一套新提示词、重新生成；② 放开生成字数限制。
> 本文只定位与设计，**不动代码**。

---

## 1. 定位：限制**只有两处**

| 位置 | 内容 | 性质 |
|---|---|---|
| `services/script.ts:23 / 35 / 47` | 三个行业的提示词都写着「**全文控制在 200-300 字**」 | **字数限制在这里** |
| `services/script.ts:176` | `max_tokens: 1024` | 硬上限 |
| `routes/scripts.ts` | **不校验正文长度**（只校验标题 ≤100 字） | ✅ 放开字数无需改校验 |

提示词原文（餐饮，另两个行业同构）：

```
你是一名本地团购商家的 AI 直播话术写手。根据用户提供的团购商品信息，
写一段用于无人直播的口播话术。要求：语气自然口语化，像真人主播在讲解；
突出套餐内容、价格与卖点；全文控制在 200-300 字；不夸大宣传，不出现广告法极限词…
        ^^^^^^            ^^^^^^^^^^^^^^^^
        单段                字数上限
```

**要放开字数，理论上只需改这两处**（提示词 + `max_tokens`），因为路由不校验。

> ⚠️ 但 `max_tokens: 1024` 到底能撑多少中文字，**我没能确证**：
> 库里有一条 **2000 字**的历史记录（说明 1024 可能够），但那条来源不明；
> 另一处参照是 `reply.ts` 用 160 tokens 产 ~100-160 字（≈1 token/字）。
> **两处口径矛盾，需要实测一次再定**（这是要执行时第一件该做的事）。

## 2. 证据：真实生成结果 vs 客户样例

云端实际数据：

```
近 8 条话术字数：474 / 2000 / 328 / 477 / 13 / 29 / 8 / 9
全库分布：      min=8  max=2000  avg=140  共 30 条
```

最近一条（474 字，餐饮）实际长这样：

> 「欢迎所有来到咱们家直播间的宝宝们…1号链接是我们的火锅大口吃肉不心疼3-4人餐: 这个套餐特别划算，单单光肉的话就有5盒…足足的11件套只需要59.9元…库存最后几单…赶紧多囤几单。」

| | 真实生成 | **客户方样例** |
|---|---|---|
| 字数 | **474 字** | **约 1500 字** |
| 结构 | **一整段** | **8 个带小标题的段落** |
| 覆盖 | 开场 + 商品详情 + 价格 + 促单 | **开场 / 引出商品 / 适用人群和场景 / 产品卖点 / 核销注意事项 / 价格福利 / 鼓励下单 / 结束语** |

**差距 = 1/3 的信息量 + 完全没有结构。**

（注意：提示词要 200-300 字，实际产出 474 字 —— **模型本来就超写了**，说明 200-300 这个数字对模型约束力有限，但它的**信息量上限仍然被框住了**。）

## 3. 为什么「简陋」是**必然的** —— 三个原因

### (a) 提示词自己要 200-300 字
信息量上限就摆在那里。**要 1500 字的输出，就不能写 200-300。**

### (b) 提示词说「写**一段**」
没有**说服弧线**：开场（留人）→ 共鸣（场景）→ 痛点 → 卖点（具体到感官）→ 价格（对比）→ 促单（CTA）→ 收尾。
「一段」这个要求本身就在阻止模型组织结构。

### (c) ⚠️ **输入字段只有 4 个** —— 这条最容易被忽略，也最关键

```ts
productFields: { name: '团购券名', package: '套餐内容', price: '价格', sellingPoints: '卖点' }
```

**客户样例里那些内容，我们根本没有素材来源**：

| 客户样例的段落 | 需要什么输入 | 我们给了吗 |
|---|---|---|
| 适用人群和场景 | 人群 / 场景 | ❌ **没有** |
| 核销注意事项（不用预约 / 随时可退 / 过期自动退 / 全国通用） | 核销规则 | ❌ **没有** |
| 开场（10 年老品牌 / 全国 10000 多家店） | 品牌背书 | ❌ **没有** |
| 产品卖点（大理石纹理 / 肉汁爆出来） | 卖点 + 允许展开描写 | 🟡 有字段但没要求展开 |

> **所以：光改提示词不够。** 输入不扩，模型只能**略过**（于是简陋）或者**编造**（于是踩我们「不编造」的合规红线）。
> **这两条路都不能走。**

## 4. 新提示词设计（草案）

### 4.1 四条设计原则

1. **结构化**：按固定段落产出，**带小标题**（不再「写一段」）
2. **放开字数**：目标 **1200-1800 字**（对齐客户样例），不设「200-300」这种硬框
3. **要具体**：数字、感官、场景画面（客户样例的「大理石纹理」「肉汁爆出来」「窝在家里」就是范例）
4. **不编造**：**没有的信息宁可略过，也不许编**（这条我们已有，必须保留）

### 4.2 段落结构（对齐客户样例 + 我们的 kind）

| 段落 | 目标字数 | 映射 kind |
|---|---|---|
| 开场 | 150-250 | `opening` |
| 引出商品（场景共鸣 → 痛点 → 引出） | 250-350 | `product` |
| 适用人群和场景 | 100-150 | `product` |
| 产品卖点（具体、带感官） | 300-400 | `product` |
| 核销注意事项 | 100-150 | `coupon` |
| 价格福利（对比 + 划算感） | 150-250 | `coupon` |
| 鼓励下单（CTA + 背书 + 下单路径） | 150-250 | `coupon` |
| 结束语 | 80-120 | `closing` |

**合计约 1280-1920 字** —— 与客户样例同一量级 ✓

### 4.3 输入字段要扩（**否则新提示词也会简陋**）

| 新增字段 | 用途 | 必填 |
|---|---|---|
| `audience` 适用人群 | 「适用人群和场景」段 | 建议 |
| `scenarios` 使用场景 | 同上 | 建议 |
| `redemption` 核销规则 | 「核销注意事项」段 | 建议 |
| `brand` 品牌背书 | 开场（老品牌 / 多少家店） | 可选 |
| `priceOriginal` 原价 | 「价格福利」的对比锚点 | **强烈建议**（没有就只能说「很划算」，很空） |

> **注意**：这些字段**可空**。空的时候提示词要明确「**该段可省略**」，绝不能诱导模型编。

## 5. 一个额外收益：结构化输出 = 可直接拆成台本

这一点与上一轮 `SEGMENTED-SCRIPT-FUSION.md` 的结论**自然接上**：

- 新话术**带小标题** → 解析器按小标题切段 → **映射到 `LOOP_ITEM_KINDS`** → 一键生成台本
- 于是「话术（喂 AI 做回答口径）」与「台本（循环播出）」**同源**，不会出现「台本说 59.9、回复说 59」

**并且这正好绕开了 R46 的边界**：
> R46 现在是「字数 ÷ 50」自适应 → 1500 字会被切成 30 段、**把 8 段的语义边界切碎**。
> 有了小标题，就应该**优先按段落切**，字数只作兜底。

## 6. 待拍板

❓ **D1 · 目标字数定多少？**
➡️ 推荐 **1200-1800 字**（对齐客户样例）。**注意上限由 `max_tokens` 决定，需先实测**。

❓ **D2 · `max_tokens` 抬到多少？**
➡️ 推荐先实测「1024 到底能出多少中文字」，再定 2048 / 4096。**不要凭猜**。

❓ **D3 · 输入字段扩不扩？**
➡️ **强烈建议扩**（§4.3）。不扩的话，要么简陋、要么编造 —— **两条都是坑**。

❓ **D4 · 段落结构采用 §4.2 的 8 段吗？**
➡️ 推荐采用（与客户样例一致、且能映射我们的 kind）。

❓ **D5 · 要不要顺带支持「导入客户方已有话术」？**
➡️ 客户方已经在手写这种结构了。若他们会持续提供，**一个解析器（按小标题切段 + 映射 kind）的价值很高**。

❓ **D6 · 旧话术怎么办？**
「重新生成」是重跑生成、还是保留旧版？➡️ 建议**生成新版并存为一条新记录**，旧的不动（可对比、可回退）。

---

## 7. 一句话总结

> 简陋不是模型不行，是**我们只要了 200-300 字的一段话**，而且**只给了 4 个字段的素材**。
> 要 1500 字的结构化话术，就得：**放开字数 + 规定段落结构 + 补齐输入字段** —— 三件事一起做。
> 只改提示词，模型只能在「略过」和「编造」之间二选一。
