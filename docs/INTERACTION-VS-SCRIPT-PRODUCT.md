## 0. 先把产品定位厘清（后面所有判断都从这里推）

这个产品对商家的承诺是什么？

> **「帮你把商品讲清楚，顺便接住观众的问题。」**

拆开就是两条线：

| | 循环台本 | 弹幕互动 |
|---|---|---|
| 作用 | 把商品讲**完整** | 接住**具体**问题 |
| 对谁有价值 | **刚进来的新观众**（他在判断「这是不是我要的」） | **已经感兴趣的提问者** |
| 产品角色 | **主线** | **支线** |

## 1. 问题一：互动会阻碍话术吗？——我上一轮**夸大了**

### 1.1 我上一轮说错了什么

我说「台本被饿死 = 功能失效」，理由是「商家开播的核心诉求是讲商品」。
**这个推理有个漏洞：弹幕回复的内容本身就是商品信息。**

观众问「多少钱」，AI 答「咱家双人火锅套餐是 99 元」——
**这句话对旁听的其他人不是噪音，而是另一种形式的商品介绍。**

所以「台本没播」并不等于「没在卖货」。**我把危害夸大了。**

### 1.2 那真正的产品危害是什么

不是「没播台本」，而是这三件事：

| 危害 | 为什么这是产品问题 |
|---|---|
| **① 重复** | 同一个问题被反复问、反复答 → 直播间变成**复读机**。旁听者听三遍「99 元」就烦了 —— 这是**掉人**的直接原因。 |
| **② 碎片化** | 商品讲解被切碎成一条条问答 → 新观众**拼不出完整的产品认知**（他在卖什么？套餐里有什么？在哪？）。 |
| **③ 时长失控** | 提示词要求「1~2 句短句」，但硬上限是 `max_tokens: 160`（折算约 100~260 字 ≈ **21~55 秒**）—— **没有任何机制阻止一条回复占用一分钟**。 |

### 1.3 所以产品目标是「节奏」，不是「保底」

我上一轮提的是「台本保底（让位超 N 秒强制播一句）」——那是**工程视角的兜底**。
换成产品视角，要的不是「保底」，而是**两条线交替的节奏感**：

> 台本是**骨架**（保证商品讲完整），互动是**血肉**（接住具体问题）。
> 骨架不能被无限打断，但也不能完全不给互动留口 —— **要的是交替，不是谁压谁**。

## 2. 问题二：弹幕太多 —— 核心是**产品逻辑错位**

### 2.1 现状（代码事实，但结论是产品结论）

```
场次级频控（按时间窗丢弃）
   ↓ 通过的才往下走
LLM 判断「这条要不要回」（灌水 → NONE）
```

**限流发生在「判断值不值得回」之前。**

### 2.2 这意味着什么（产品语言）

**等于先抽签、再验货。**

- 一句「666」可能抽中名额，把真正的提问挤掉
- 而**有能力分辨这两者的 LLM，根本没机会看到它们**（被时间窗挡在前面）

**「值不值得回」和「什么时候回」本来是两件事，现在被一个时间窗混成了一件。**

### 2.3 产品正确的顺序

1. **先验货**：这条值不值得回？（挑选）
2. **再排期**：值得回的进队列，队列决定什么时候回（节奏）

这样「灌水」根本进不了队列，不占名额；而「问题」不会因为抽签运气差被丢。

## 3. 产品基准：一个真人助播会怎么做

面对同时涌来的 20 条弹幕，真人助播的行为是**有章法的**：

| 真人怎么做 | 我们现在 |
|---|---|
| 扫一眼，**挑有信息量的**（问题 > 互动 > 灌水） | ❌ 不挑，**先到先得** |
| 同类问题**合并答一次**（「好几位朋友都在问价格」） | ❌ 一条一问一答 |
| 答不上的**记下来**（等主播或稍后） | ❌ **答不上就丢**，没有任何痕迹 |
| 灌水**完全无视**（不消耗注意力） | ❌ 灌水照样占名额 |

### 三个产品缺口

1. **挑选** —— 谁值得回
2. **合并** —— 同类问题答一次（我上一轮把它排成「二期」，**产品上错了**：这是最自然的做法，应该早做）
3. **不丢** —— 没轮到的、答不上的，**至少让商家看得见**（现在商家完全不知情）

## 4. 一个更根本的产品问题：频次档位的语义错了

我给商家的六档是 **「1 秒/次 · 5 秒/次 · 10 秒/次 · 20 秒/次 · 自定义 · 不回复」**。

这是**工程师的语义**（节流间隔）。**商家脑子里想的不是这个。**

商家真正担心的是两件事：
- 「**会不会漏掉观众的问题**」（怕漏）
- 「**会不会太吵**」（怕烦）

而现在这个档位只表达了「多久回一条」，**完全没有表达「漏多少」**。

> **商家怕的是漏，我们给的却是限流。这是一个方向性的偏差。**

产品上更贴切的语义可能是：**「尽量都回 / 平衡 / 少回 / 不回复」** ——
而「限流」应该是**按重复**（同一个问题 60 秒内不重复答），而不是**按总量**。

## 5. 待拍板（都是产品口径问题）

❓ **P1 · 产品的第一目标是「不漏问题」还是「不吵」？**
两者冲突时谁让步？➡️ **我倾向「不漏」**：漏一条问题 = 丢一个可能下单的人；吵一点只是体验差。
**但这需要你确认** —— 它决定了后面所有取舍。

❓ **P2 · 频次档位的文案要不要改成产品语言？**
现在「5 秒/次」是工程语义。➡️ **建议改成「尽量都回 / 平衡 / 少回 / 不回复」**，秒数藏在副标题里。

❓ **P3 · 回复的长度上限要不要收紧？**
现在硬上限折算下来可能到 21~55 秒。➡️ **建议按「口播时长」定上限**（比如 15 秒），而不是按 token。

❓ **P4 · 要不要「合并同类问题」？**
我上一轮排成二期，**产品上错了**。➡️ **建议提前**：它是最像真人的做法，而且直接解决「复读机感」。

❓ **P5 · 没回上的弹幕要不要留痕给商家？**
现在商家**完全不知情**。➡️ **建议留**：至少显示「本场收到 N 条，回了 M 条」。
**不显示，商家就无法判断自己的设置是不是太紧。**

## 6. 一句话总结两轮讨论的差别

| | 上一轮（工程） | 这一轮（产品） |
|---|---|---|
| 问题一 | 台本会被**无限饿死**，要**保底** | 危害被我夸大 —— 回复内容本身也是商品信息；真正的危害是**重复 / 碎片化 / 时长失控**；目标是**节奏**不是保底 |
| 问题二 | 纯丢弃，要**队列 + 优先级 + 覆盖率** | 核心是**逻辑错位**：先抽签后验货；应该**先挑选再排期**；缺口是**挑选 / 合并 / 不丢** |

> **工程答案没错，但产品理由错了** —— 而理由错了，优先级就会排错（比如我把「合并同类」排成了二期）。
