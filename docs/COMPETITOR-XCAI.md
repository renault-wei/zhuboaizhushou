## 3. 判断结论：竞品走的是灰色路线（证据链）

1. **弹幕 = 独立「弹幕助手」采集，非官方通道**：日志明示按平台逐个适配（小红书改用「分享直播间链接」连弹幕），
   属我们方案文档里 D 类「自动读取」的更强变体（逆向/非官方连接 + 多平台）。这类通道平台一改就会断，
   竞品 2026.06~08 连续三次更新弹幕助手即为佐证。
2. **平台名全部打码**（某音、某手、小红薯……）：规避平台检索与投诉的常见写法，合规软件无需如此。
3. **核心卖点 = 对抗平台风控**：「抗封」「协助通过部分平台的声纹检测机制」「碎片化伪装真人、可拉十几天」——
   产品定位本身就是跟平台规则对着干，靠的是规避检测而不是平台允许。
4. **「AI 回复公屏弹幕 10s 内」= 无人值守 AI 自动直播**：真实弹幕自动读取 + AI 自动回复（公屏互动），
   是平台违规高发区（自动回复 / 无人直播需按平台规则申报，未申报即违规）。

## 4. 与我们方案的关系与取舍（沿用既有红线）

- 它的功能卖点（AI 读弹幕 + AI 回复 + 商用 TTS/克隆音色 + 语音进直播伴侣）与我们的 G3~G6 已落地链路**同构**，
  差别只在「采集侧 + 抗封手段」这两块黑盒。
- 结论：**功能清单可以借鉴；灰色采集与抗封玩法不做**（AGENTS 合规红线：违规即 bug）。
- 弹幕采集口径维持已拍板方案（见 `docs/DANMAKU-CAPTURE-PLAN.md`）：一期 B 人工中转（已实况验收）
  → 二期 C 屏幕 OCR 半自动 → 全自动等官方通道或挂靠有资质服务商后再评估。
- 若未来上架 SaaS：「自动读弹幕」「绕过风控/抗封」当卖点 = 把封号、限流风险转嫁给商家，属产品红线，不进 PRD。
