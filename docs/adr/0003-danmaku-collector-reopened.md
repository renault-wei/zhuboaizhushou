# 重启弹幕采集专项（D 系列）：从「已结项」改回进行中

## Status

accepted

## Context

2026-09-08，弹幕采集专项（D 系列）在开发到 D2.3 后被整体关闭，记录在 `docs/DANMAKU-COLLECTOR-PLAN.md`，
拍板原话是「弹幕抓取需求先关闭，其余收尾 / 结项」。当时关闭的**硬**阻塞只有一个：签名环节拿不到可用的 Key。

自研抖音 wss 必须先把房间号换成带签名的 wss 地址，而这一步由第三方签名服务**在服务端完成，本地无法伪造**。
当时试过两把 Key，都不行：

- 竞品 APK 里提取的那把 —— 属**他人账户资产，明确禁止复用**；
- 用户手中的 AIOBS 官方试用 Key 是 GUID 形态 —— 实测返回 `{"Code":-1,"Msg":"ApiKey is invalid."}`，
  事后证实它是桌面客户端的激活卡密，不是 Web API 签名 Key（见 `docs/COMPETITOR-XCAI.md` §6.4 / §6.5）。

于是当时的结论写成：「需另购 SignWss 可用的 Web API Key（命名应为 `apikey-dy-*`），到手后重跑 `sign:smoke` 验收」。

## Decision

**该前置条件已满足，专项重启。** 用户提供了 `apikey-dy-*` 格式的 Web API Key，探针实测返回 `Code:0` 与带签名的 wss 地址。

交付边界固定为 **自用自测**：自有直播间、低流量、以观众身份连接公开网页端。
对外产品分发是**另一个决策**（需要 AIOBS 合伙人档及以上授权，并承担平台风控连带），不在本批次。

## Consequences

- `AGENTS.md` 的范围描述与计划文档的状态同步翻转；**结项原文保留不改写**，只在头部追加重启声明。
- 关闭期间留下的 `server/src/collectors/*`（约 1600 行）**原样复用**：当初就是按"未来重启可复用"设计的。
  本次盘点确认 D0.1 / D0.2 / D1.1 / D2.1 / D2.2 / D2.3 已完成，缺口集中在 D3.1（落库与幂等）、
  D3.2（采集控制 API）、D5.1（事件接线）—— 即"模块写完了，但没有任何生产调用点"。
- **合规红线不变**：不做抓包与私有协议逆向、不模拟发包、不做多账号批量采集、不绕过限流与风控、
  不把"采集他人直播间弹幕"做成对外能力或销售承诺。AI 智能直播角标恒开不变。
- **主动接受的代价：引入一个新的第三方凭据面**（AIOBS 签名服务）。这与仓库原有的"不引入新凭据面"倾向相冲突；
  接受它的理由是该专项的验收无法在本地伪造，且关闭期间已经证明"换一把 Key"是唯一可行路径。
- 非官方通道的固有风险：平台改版即可能集体失效，且可能牵连风控。
  缓解 = adapter 失效时 fail-stop，只停该场采集，出声链路不受影响。
