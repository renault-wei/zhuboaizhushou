# 正本仓库位置：dsh-space 副本

## Status

accepted

## Context

同一个项目在本机存在两份**内容相同、资产不同**的工作副本：

- 新克隆的副本（`D:\dsh-space\zhuboaizhushou`）：工作树干净，不含任何密钥；但也不含运行所需的本地配置与交付归档。
- 原开发副本（`D:\codex_project\2026-09-06\give-me-skill\work\zhuboaizhushou`）：含运行必需的本地密钥配置、一个历史 stash，以及交付归档（云版安装包、真机截图、取证音频）。

两份副本并存时，任何一边提交都会让另一边**静默落后**，"最新代码在哪"会重新变成一个需要考古的问题。
接手时的第一个坑正是它：默认克隆拿到的是默认分支，而项目真正的工作分支领先它近百个提交。

## Decision

以新克隆的副本为**正本**，所有开发与提交只发生在正本。
原开发副本原地**冻结为只读参考**，仅作为其独有资产的来源。

## Consequences

- 本地密钥配置不入版本库（仓库红线），只能人工从旧副本转移到正本；**转移完成前不得删除旧副本**。
- 旧副本中位于**仓库之外**的中间产物是当时唯一的比对物，在正本完成一次实测验收之前不删除。
- 旧副本禁止再提交：任何"两边都改一点"的做法都会重新制造分叉。
- 正本在被重新检出到真正的工作分支之前，其工作树仍停留在默认分支——新写的文件在提交前应视作"未落到任何分支上"。
