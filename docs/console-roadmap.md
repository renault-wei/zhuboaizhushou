## 1. 范围与边界

**做**（本方案 M1~M4，落地顺序 = 跑通自用闭环优先）：
- 公司账号登录（admin_users，只允许运营预置账号，**不开放注册**）
- 商家（租户）台账：手机号 / 订阅 / 注册时间 / 资源用量汇总
- 算力与额度：额度行查看与运营调整（月度周期），AI 用量流水查看
- 金额与订单：订阅/充值订单列表、支付状态、运营补单（人工确权）；v0.3 增扫码单、卡密批次与核销、系统开关
- 数据看板：北极星指标 = 商家数 / 订阅订单收入 / AI 用量 / 进行中直播
- 审计留痕：运营所有写操作进 audit_logs

**不做**（一期明确排除，避免冒进）：
- 商家自助注册 / 自服务改套餐 —— 仍排除；面向商家端 App 的收银台（扫码展示 / 卡密核销 UI）延到 M7 手机线批次
- 真实微信支付证书 / 支付宝当面付凭证真调 —— 凭证未就绪前一律走 mock 演示单 + 运营人工确权，遵守 AGENTS「真实支付不擅自实现」
- 云部署 / 多租户白标隔离（OEM 谈单后另立）—— `app_config` 本期只做全局开关，Key 结构预留 merchant 维度
- 计费单价配置页 —— 并入 v0.3「系统开关下发」统一做（服务端配置，不单独建页）
- 内容审核的“全自动放行”：仍按合规红线拦截，后台只做只读队列 + 授权存档

> v0.3 说明：AGENTS v0.2「不做多档套餐」口径随本次商业化修订解除 —— 预充时长档位由服务端配置下发，不再走订阅套餐枚举。

## 1.5 计费模型 v0.3（2026-09-08 修订，doc-only）

**决策来源**：竞品 xcai1618 反编译观察 —— 无 App 内支付 SDK（无 uni.requestPayment / plus.payment），
充值 = 服务端生成支付宝收款码 + 客户端只展示 + 服务端轮询对账确认；售卖凭证 = 卡密（批次 / 分销 / 核销）；
运营开关全部服务端下发（充值入口显隐、时长档位、公告等）。用户拍板：采纳该形态。

**形态**（替换原 ¥99/月订阅主路径，历史订阅订单保留为 legacy 类型）：
1. **服务端扫码直充**：商家按「时长档位」下单 → 服务端 `POST /api/recharge/scan` 生成扫码单；
   凭证未就绪阶段返回 mock 占位说明、状态 pending；确认入账两条路 = 凭证接入后的服务端查单轮询，或运营后台人工确权（复用 M2 confirm）。
2. **卡密批次核销**：后台按批次生成卡密（每张 = N 分钟时长），线下 / 渠道分发；商家端输入卡密核销即入账 ——
   **不经过任何真实资金接口**，可先于收款资质完整离线验收。
3. **服务端开关下发**：`app_config`（key→jsonb）全局下发：充值入口显隐、时长档位与单价、公告弹窗、扣减优先级等；
   `GET /api/app/config` 供商家端读取，改配置不改版。

**账本（两本账，与 M4 免费试用档共存）**：
- `quotas`（月度，免费试用 / 赠送上限）：TTS 字符 / 话术生成次数 / 直播分钟 —— 维持现状，做成本守门。
- **时长余额账户（新增）**：预充小时包的核销入账，跨月不清零，按「AI 在线 / 轮播分钟」扣减。
- 扣减口径（默认，可配置）：直播在线分钟先扣时长余额；余额为 0 → 回落当月免费直播分钟；再尽 → 402 引导续费。
- 扫码 / 卡密均为「充值订单」（kind=recharge）入账：paid 时写时长余额 +1 条流水，审计留痕沿用 audit_logs。

**收款合规线（红线）**：真实扫码收款 = 运营主体支付宝凭证（当面付商户号 / 商家码）就绪后由 M8 接入；
凭证不硬编码（沿用 .env 机制）；本地自用验收阶段不真调任何支付接口。

## 3. 服务端设计口径

- 鉴权：默认 JWT 保持商家端语义不变；新增 **admin 命名空间**（`@fastify/jwt` namespace），
  载荷只放 `{ adminId }`，每次请求回查 `admin_users` 有效在岗账号；杜绝商家 token 冒用后台。
- 口令：bcrypt 哈希只存 admin_users.password_hash；初始账号走 `npm run admin:seed` 脚本（env 读入，不留默认口令）。
- 额度：`quotas` 唯一键 (user_id, period)，period=YYYY-MM。商家首次调用第三方 AI 时按「免费试用档」自动建档
  （本自用阶段放量：TTS 字符 50 万/月、话术生成 300 次/月、直播 2 万分钟/月，数值可运营调整）；
  额度归零后返回 402 `QUOTA_EXCEEDED` + 引导续费文案（合规成本红线，不做关闭开关）。
- 用量：每次第三方 AI 调用成功写一条 usage_logs（category=script_generation 等；provider/model/promptChars/outputChars）；
  本地 mock / 本机 SAPI 不落成本金额（costCents=0，等接真实计费单价表再算）。
- 订单：商家 `POST /api/orders` 生成 pending（¥99/月=9900 分）；运营在后台「确认收款」= 模拟支付回调，
  把订单置 paid + 订阅顺延 30 天 + 当月额度按付费档刷新（幂等：重复确认 409）。
- v0.3 订单模型扩展：orders 增加 `kind`（subscription|recharge）/ `channel`（manual|alipay_scan）/ `hours`；
  `wx_transaction_id` 作为可选渠道单号保持可空 —— 订阅（历史）与充值（扫码/卡密）共用一张表，看板收入按 kind 聚合。
- v0.3 新增表（drizzle 迁移，禁止直改表）：`card_batches`（批次：名称/总张数/单张时长分钟/状态/备注/创建人）、
  `card_codes`（卡密：批次外键/卡密唯一/状态 unused|redeemed|revoked/核销人/核销时间）、
  `app_config`（key→jsonb：showCharge 充值入口显隐、pricePacks 档位 [{hours, amountCents}]、notice 公告、
  quotaPriority 扣减优先级；含 updated_by / updated_at）。
- v0.3 商家端 API（供 App 调用，均 JWT 鉴权 + 幂等）：`POST /api/recharge/scan`（下单 → 返回 order+qrcodeUrl）、
  `POST /api/recharge/poll`（轮询确认入账）、`POST /api/cards/redeem`（卡密核销入账）、`GET /api/app/config`（开关下发）。
- v0.3 管理端 API：卡密批次生成 / 列表 / 批次明细（核销状态）、订单接口扩展 kind/channel/hours 筛选、
  app_config 读写（写操作落 audit_logs）。
