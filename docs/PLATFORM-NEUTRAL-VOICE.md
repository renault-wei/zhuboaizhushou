# 平台无关的 AI 语音助播（定位口径定稿 · 2026-09-08）

> 状态：文档定稿（doc-only，不动代码）。
> 2026-09-08 结项注记：真实平台弹幕采集（D 系列自研内嵌）已关闭，本文「弹幕源 = 外挂 / 人工补位、不自研采集」
> 为对外基准口径；自研离线采集代码保留于 `server/src/collectors/*` 仅作技术储备（记录见 docs/DANMAKU-COLLECTOR-PLAN.md）。
> 触发：对照竞品（XCai / 星辰语音）「一套产品适配多直播平台」的形态讨论，
>   用户追问「是不是把直播平台限制放宽，本质只是用虚拟声音替真人持续开播即可」。
> 结论：是。产品定位收敛为**平台无关的 AI 语音助播**，本文记录口径、边界与落点。

## 1. 一句话定位（2026-09-08 收敛）

> 商家在自己选的直播平台开播（抖音 / 快手 / 视频号…，画面与卖货由商家自己搞定），
> 我们的 App 作为**后台 AI 语音主播**接入：循环台本口播 + 弹幕问答，持续出声。

- 卖什么、什么画面、在哪个平台播 → 商家负责；
- AI 说话、回弹幕、介绍产品 → 我们负责；
- 只要商家开播、把我们的声音接进直播间，AI 就持续工作，**与平台无关**。

## 2. 为什么成立：主链路三段本来就是解耦的

| 段 | 职责 | 是否依赖具体直播平台 |
|---|---|---|
| 采集端（弹幕源） | 以观众身份监听弹幕 → 转发网关 | **是**（唯一平台相关点） |
| AI 大脑（后端） | 收弹幕 / 轮播台本 → DeepSeek 生成 → 火山 TTS 合成 → 入出声队列 | 否 |
| 出声端（助播机） | 拉取播放队列，把 AI 语音送到直播间 | 否 |

- 声音出口天然跨平台：直播平台只认「听到的声音」，不认声音从哪来。
- 弹幕是唯一绕不开平台的地方，但已外挂化：用市面上的「弹幕助手」类成品 / 开源适配，
  转发到既有网关 `POST /api/lives/:id/danmaku`，业务侧零改动（见 `docs/DANMAKU-CAPTURE-PLAN.md`）。
- 每个平台 = 换一个弹幕适配器，不是重做产品；没有对应弹幕源时，纯轮播（口播产品）依然成立。

## 3. 与仓库红线的边界（不冲突）

- 仍**不做多平台推流**：我们不推流、不替商家开播，只出声 → AGENTS「不做多平台推流」红线不变。
- 托管无人直播（G1/G2）维持暂停待抖音 key，非当前主形态；主形态 = 真人出镜 / 实景 + 后台 AI 语音（G5/G6/G7 已落地部分）。
- 弹幕仍只覆盖「自己账号、自己直播间、自用自测」，合规红线与 `docs/DANMAKU-CAPTURE-PLAN.md` 一致。

## 4. 商业模式口径（随定位一起收敛）

- 计费锚点 = **AI 在线直播时长 / 轮播量**：商家直播期间 AI 语音持续播报，按直播消耗计费（对齐既有免费额度「2 小时直播」与订阅模型）。
- 话术由 DeepSeek 生成（可循环播），回复也走 DeepSeek；成本大头是 TTS（火山按量），定价与算力额度口径沿用公司端任务台配额体系（`docs/console-roadmap.md`）。
- 计费与平台解耦：无论商家在哪个平台播，只要 AI 在线就计量，天然支持未来的多平台客群与 OEM。

### 4.1 每小时成本锚点（2026-09-09 立项口径）

- 目标：**AI 语音在线 1 小时总成本 ≤ 0.4 元/小时**（固定循环台本口播场景；含 DeepSeek 文案生成 + 火山 TTS 新合成）。
  该锚点同时是「按直播分钟计费仍有毛利」的必要条件（对商家按时长 / 算力收费赚差价的结构性前提 = 单位小时真实新合成成本足够低）。
- 衡量指标：**每小时新合成字符 ≤ 2000 字符**。固定台本循环首轮预热写入分句缓存后，后续循环全部命中缓存、不触发新 TTS；
  新合成只来自首轮预热、台本改动与弹幕回复（弹幕回复本身限流插入）。
- 命中路径（hit-path）：循环台本首轮预热 → 全缓存命中循环 → 新合成 ≈ 0；弹幕回复走频控插入，属低频新合成。
- 竞品佐证：见 `docs/COMPETITOR-XCAI.md` §7 —— 便宜来自「服务端一次合成 + 播放端缓存 / 历史回放复用」的结构，而非供应商单价。
- 落地里程碑：`docs/LOWCOST-AUDIO-PLAN.md`（T3 分句缓存 → T6 云端实测，成本达标以实测入档为准）。
