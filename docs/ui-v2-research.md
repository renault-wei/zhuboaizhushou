## 1 竞品「直播」Tab 与直播间的 UI 结构

### 1.1 App 级结构：3 Tab + 深色设计口令

竞品底部 TabBar 固定 3 个：`首页` / `直播` / `个人信息`（`source\beautified\app-service.js` L34770-34790）。配色口令：

- TabBar 底色 `#080810`（近黑）、选中色 `#11e27d`（荧光绿）；
- 直播页系整体 `#131b21` 深底、白色文字为主；
- 直播 Tab 与个人页使用自定义导航（沉浸感更强），非系统默认 AppBar。

**可借鉴判断**：竞品用「深色底 + 单一荧光绿」形成强品牌记忆点。我方不必照抄颜色，但「固定 3 Tab + 直播页深色沉浸」的方向一致可行。

### 1.2 直播 Tab 主界面 `pages/live/live`（PagesLiveLive，L61022-61127）

自上而下的页面分区：

1. **标题区**：`直播间 + 直播位号`（显示当前生效的场次/直播位），右上可能有状态信息。
2. **统计条 `.function-module`**：总直播时长、有效期，以及全局「强制关播」按钮（仅直播中可点，红色渐变胶囊）。作用是把「全局兜底控制」放主列表层，用户不必钻进每个直播间找关播。
3. **直播任务卡片列表 `.list`**：每张卡片 = 可改名的标题 + 👈 手势引导 + 直播时长图标文案 + 右侧「开始直播 / 删除」胶囊按钮。文案极直给，无营销修饰。
4. **页底大按钮**：「创建直播任务」，90vw × 10.6vw 绿底深字胶囊。
5. **复用对话框** `cc-defineDialogBox`：承担卡密归因 / 兑换归属 / 建任务确认等（`chargeToUser`/`chargeTobeizhu`/`cardToUser`），说明它的「创建任务」默认绑定卡密计费逻辑。

**视觉规约摘录**：卡片 `rgba(0,0,0,.3)` 圆角 16px；主渐变 `linear-gradient(90deg,#11e3b5,#11e37e)`；次级文字 `#7282a1`；字号用 `vw`（约 2.8~4vw）做弹性；「续费」带 👈 摆手动画（`hand-wiggle`）。

**对直播 Tab 的启示**：
- 场次列表是「一卡一场」的实体卡片（任务粒度），比状态表格更直观；
- 「直播中/草稿/已就绪」等状态要在卡片上直接可视，而不是藏在详情里；
- 全局兜底「停止全部/强制关播」放列表层是有价值的，我方保留「监控工作台才可开播」的并发控制的同时，可考虑在列表页给「直播中」提供只读状态 + 一键进入，强制关播仍留在工作台内（安全红线不变）。

### 1.3 直播间工作台 `pages/feedback/index-app`（PagesFeedbackIndexApp，L57515-58397）

这是竞品的「AI 直播间控制台」，信息量最大，结构如下：

1. **身份区 `.sign-info`**：头像 + 算力余量（小时数）+「复制您的直播位 ID 以接收弹幕」+ 复制按钮。直播位 ID 是竞品的弹幕中转绑定凭据。
2. **内容表单区**（自上而下）：
   - 主播发音人 / 助播发音人（双角色）；
   - 参考话术 textarea；
   - 智能客服商品描述 textarea（让 AI 兜底回答商品问题）；
   - 直播间分享链接 textarea。
3. **「实时互动配置」区**：
   - **基础配置**：智能发挥模式（自由 / 半自由 / 关闭；提示「文案 >30000 字仅支持全自由」）；用户接待 checkbox（欢迎 / 回复 / 报时）；忽略昵称（`|` 分隔）。
   - **高级配置**：定时切换主播/助播音色（多选 + 1-1440 分钟）；欢迎/关注/点赞/回复/报时语设置，支持 `{A|B|C}` 随机、`[昵称]`/`[答案]`/`[问题]`/`[时间]`/`[在线人数]` 变量、每类频率上限与字数（500 字、1-300s、1-60s、60-3000s）；定时关播（分钟，≥10）；语速区间；音频间隔随机；违禁词设置（顿号分隔、禁单字符）。
4. **启动与权限区**：「开始直播」+「缩小悬浮窗/还原悬浮窗」+「检查权限」+「开启权限以持续接收弹幕」四步图文引导（悬浮窗 / 通知 / 应用启动管理）。

**对直播间的启示**：
- 竞品把「配置内容」与「实时开播」合在一页，可一次完成「填好→开播→缩小悬浮窗」。我方建议拆为「完善场次（配置表单）」与「工作台（实时监控）」两屏，但开播前的必填引导要做到一次成型。
- 双角色（主播/助播对谈）已是竞品默认配置，与我方「双虚拟人对谈生成」方向一致。
- 权限四步引导（悬浮窗/通知/自启动）在 Android 实机上是刚需，建议做成首开引导组件复用。

### 1.4 悬浮窗 `pages/live/new-float`（PagesLiveNewFloat，L5769-5856）

直播中的迷你面板：

- 隐藏钮 → 6 宫格统计：已播时长 / 在线人数 / 累计人数 / 弹幕数量 / AI 回复次数 / 算力剩余；
- 弹幕连接状态 pill + 弹幕 ticker（横向滚动）+ 营销横幅；
- 三个动作钮：「重连弹幕 / 音频(暂停/开始) / 关闭直播」；
- 兜底遮罩「点我开播」。

**启示**：悬浮窗是「直播中状态」的最佳载体，比切回主 App 更接近真人盯播体验。6 宫格 + 弹幕 ticker 的密度合适，可作为我方直播 Tab「直播中」卡片的同构展示（在工作台内复用组件而非新写）。

### 1.5 音库/克隆 `pages/feedback/audio`（PagesFeedbackAudio，L41395-42205）

竞品克隆页是「表单 + 播放器 + 音色列表」三段式：

1. 折叠「免责声明」；
2. 分步克隆：声音模型名称 → 选声音模型 → 选克隆模式（**自训练 5-15 分钟**（标注强情感/抗声纹检测）/ **随机色男女模式**（免素材，带「限时免费」）/ **经典 6-15 秒克隆**）→ 性别 → 上传（mp3/m4a/wav）→「开始克隆」；
3. 下方播放器区：循环 / 语速切换 / 进度条 / 退 15s / 播放 / 进 15s；
4. 音色列表分区：**系统内置精品音色** / **您的靓音（创建于 xx）**，支持试听、自定文本试听、删除、恢复。

**启示**：我方首页「声音克隆」入口对应的核心是「预设音色（火山引擎预制）+ 克隆音色」两类，其中克隆流程当前已收紧为 2 段录音（用户已确认）。竞品「内置音色单独成区、克隆音色可恢复」的结构可直接作为音色库分组参考；播放器交互（试听 + 自定文本试听）值得抄。

## 2 竞品「个人信息」页模块清单与展示方式

页面 `pages/dulin-setting/userInfo`（PagesDulinSettingUserInfo，L61487-61671），自上而下：

1. **头卡**：头像 + 昵称 + 算力余额（X 小时）+ 绑定手机号 + 「充值算力」CTA（拉起支付宝充值组件 `suanliAlipay`）。
2. **`.times` 区块**：大字「直播时长：X 小时」+ 充值按钮。
3. **「我的默认直播位」**：单选列表展示当前各直播位（状态：待激活 / 已播放 X 小时 / 直播中），决定「当前用哪个场次」。
4. **两张大 Banner**：跳运营活动页 / 用户条款。
5. **工具组**：兑换卡密、使用教程。
6. **菜单表**：隐私政策、地址管理、账户安全、官方客服（拨号）、官方客服微信（复制）、账号注销、检查更新、退出账号。
7. **底部**：版本号。

**判定**：竞品个人页 = 「余额（算力时长）+ 直播位（默认场次）+ 卡密兑换 + 客服/协议/账号」的强商业化个人中心；「充值」被反复在头卡与时长区强调。

**我方差异建议**：我方不做「卡密归因到人」的复杂玩法起步，个人页聚焦：账号信息（脱敏手机号/头像昵称）→ 钱包（余额/充值记录/扫码支付）→ 通用设置与协议（隐私/用户协议/客服/关于/退出），并在「直播 Tab」放默认场次选择，避免账号页与场次页职责重叠。AI 角标相关合规开关与说明也放个人页（不可关闭，仅展示说明）。

## 3 我方三 Tab 信息架构与视觉方向建议

### 3.1 差异总览

| 维度 | 竞品 | 我方 v2 建议 |
|---|---|---|
| Tab 结构 | 首页 / 直播 / 个人信息 | 首页 / 直播 / 我的 |
| 首页 | 偏营销与跳转 | 三大主入口：**声音克隆 / 话术 / AI 直播**，顶部保留状态化开播横幅（有场次时） |
| 直播 | 直播位 + 任务卡片 + 工作台 | 场次列表 + 完善/工作台 + 直播中悬浮（入口信息前置） |
| 个人 | 算力余额 + 直播位选择 + 卡密 + 客服 | 账号 + 钱包/充值 + 协议/客服/退出 + AI 说明（移除抖音绑定） |
| 抖音绑定 | 有（账号体系内） | **首页/账号均移除**；直播间仅用「链接/场次」承接，不绑账号 |

### 3.2 「直播」Tab 视觉设计方向（比竞品更有设计感）

**方向关键词**：深色沉浸 + 渐变大按钮 + 状态发光点 + 卡片留白。

- **页面底色**：深色 `#0F1218` 系，比竞品更接近「舞台/直播间后台」氛围；
- **主色**：单个高饱和品牌色（如荧光绿或电光蓝）只用于「主行动按钮 / 直播中状态」，不与多色混淆；
- **场次卡片**：横向单卡 = 左侧圆形缩略区（品牌渐变占位/实景封面）+ 中间「场次名 + 文案状态徽标 + 关键指标一行」+ 右侧主胶囊（去完善/开始直播/进入监控）。**直播中卡片**带呼吸光环 + 大号「● LIVE」脉冲点；**草稿**做半透明 + 虚线描边表达「未就绪」；
- **状态徽标**：待完善（灰）/ 已就绪（绿）/ 直播中（红点脉冲），与首页开播横幅同源；
- **统计入口**：不铺整条统计栏，改为右上角「时长 / 算力」轻量文字，详情进工作台看 6 宫格；
- **空态**：大号插画 +「创建第一个 AI 直播间」+ 主渐变按钮，替代竞品的列表底部按钮；
- **列表层兜底**：仅直播中可见「强制关播」，置卡片底部次级红色文字链，主停止操作仍收敛在工作台。

**组件清单（后续实现用，非代码）**：状态徽标 Badge、LIVE 脉冲指示器、场次卡 LiveCard、创建/完善大按钮、空态组件、直播中摘要条（时长/在线/算力）、工作台 6 宫格、弹幕连接 pill + ticker、悬浮窗迷你面板、权限四步引导。

### 3.3 首页差异 IA

- 去掉「抖音账号绑定卡片」（`/douyin-bind` 路由及其入口下掉）；
- 顶部保留状态化「AI 开播」主横幅（草稿→去完善；就绪→去开播；直播中→进监控）；
- 三个大功能入口宫格：**声音克隆**（→ 音色库/克隆）、**话术**（→ 台本库/生成）、**AI 直播**（→ 直播 Tab）；保证任意入口都能闭环到直播。

### 3.4 三 Tab 文案语气

竞品文案「直给、命令式、无营销感」。我方建议：主行动用「开播 / 去完善 / 进入监控」短动词；状态用「待完善 / 已就绪 / 直播中」；增值说明（AI 回复、克隆免责）用小字副文案，不抢主行动。
